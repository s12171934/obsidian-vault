# 폴더 구조 규칙

> 볼트의 최상위 폴더 구성, git 추적 경계와 도메인 사이의 의존 방향, 새 노트·자산을 어느 폴더에 둘지 판정하는 규칙이다.
> 최상위 폴더 하나는 도메인 하나다. 각 도메인 안의 세부 구조는 그 도메인 `_index.md` 의 내부 규정이 정한다.

## 1. 원칙

- **도메인 = 최상위 폴더** — 노트가 어느 도메인에 속하는지가 곧 위치다.
- **도메인이 아닌 최상위는 기반 장치뿐이다** — 공유 부품(`90_Shared/`)과 첨부 버퍼(`Attachments/`)만 허용한다.
- **이름은 역할로 짓는다** — 도구·제품 이름(Orca, Obsidian, 특정 스킬 등)을 폴더 이름에 넣지 않는다.
- **번호는 10 단위다** — 새 도메인은 비어 있는 60·70·80 을 쓴다. 90 은 기반 레이어 몫이다.
- **사람은 볼트에 직접 쓰지 않는다** — 사람의 입력은 에이전트 세션(채팅)으로 받고, 에이전트가 해당 도메인에 노트로 남긴다.

## 2. 최상위 구성

| 폴더 | 종류 | git | 담는 것 |
| --- | --- | --- | --- |
| `00_Vault/` | 도메인 | 추적 | 볼트 자체를 다스리는 규칙과 템플릿 |
| `10_Projects/` | 도메인 | 무시 | 완료 조건이 있는 일 |
| `20_Agents/` | 도메인 | 추적 | 에이전트 행동 정의 — 스킬과 작업 규칙 |
| `30_Automations/` | 도메인 | 무시 | 배치 등록부 — 트리거 묶음, 이 환경의 설정, 상태, 운영 노트 |
| `40_Tools/` | 도메인 | 추적 | 볼트 밖에서 도는 도구의 명세 |
| `50_Knowledge/` | 도메인 | 무시 | 학습·참고 지식 |
| `90_Shared/` | 기반 | 추적 | 재사용 부품 — 스크립트·프롬프트, 공용 규칙·참조 |
| `Attachments/` | 기반 | 무시 | R2 업로드 전 첨부의 임시 버퍼 |

- 루트에는 `AGENTS.md` · `CLAUDE.md` · `_Home.md`(추적)와 `CHANGE_LOG.md`(무시) 네 파일만 둔다. `.gitignore` 는 저장소 설정 파일이라 예외다.
- 추적 대상은 공개 저장소에 올라간다. 추적 문서에 넣을 수 있는 내용은 [[공개 저장소 규칙]] 이 정한다.

## 3. 추적 경계와 의존 방향

- **추적 = 정의, 무시 = 인스턴스·기록** — 추적 도메인은 다른 기계·볼트에 복제해도 그대로 쓸 수 있는 정의다. 무시 도메인은 이 환경에서 무엇을 돌리고, 무엇을 했고, 무엇을 알게 되었는지다.
- 참조는 아래 방향으로만 건다. 역방향이 필요해지면 그 공통 부분을 아래 층으로 내린다.

```
30_Automations ──▶ 20_Agents · 40_Tools ──▶ 90_Shared
```

- **`90_Shared` 는 아무것도 참조하지 않는다** — 누가 자신을 쓰는지 모르는 부품이다.
- **`20_Agents` 와 `40_Tools` 는 `90_Shared` 만 참조한다** — 둘이 서로 필요해지면 공통 부분을 `90_Shared` 로 내린다.
- **`30_Automations` 는 셋 모두를 참조하고, 누구도 `30_Automations` 를 참조하지 않는다.**
- **추적 문서는 무시 도메인으로 위키링크를 걸지 않는다** — clone 한 환경에서 깨진다. 무시 쪽은 백틱 경로 관례로만 언급한다 (`10_Projects/<프로젝트>/작업 기록/`).
    - 예외는 [[_Home]] 의 「로컬 전용 도메인」 절 하나다. 연결 체인을 유지하기 위해서다.
- `00_Vault/` 의 규칙은 모든 도메인에 적용되지만, 규칙 문서 역시 추적 문서라 무시 도메인으로 위키링크를 걸지 않는다.

## 4. 배치 판정 순서

위에서부터 묻고, 처음 해당하는 곳에 둔다.

1. 외부 도구가 파일의 형식이나 위치를 강제하는가? → 그 위치 (루트 진입 문서, `20_Agents/skills/<skill>/SKILL.md`, `Attachments/`)
2. 볼트 자체(노트 작성·폴더·링크·태그·이력)를 다스리는 규칙인가? → `00_Vault/`
3. 재사용 가능한 실행 자산(스크립트·프롬프트)이거나, `20`·`30`·`40` 중 둘 이상이 쓰는 규칙·참조인가? → `90_Shared/`
4. 에이전트의 행동을 정하는 스킬이나 규칙인가? → `20_Agents/`
5. 트리거로 무엇을 언제 돌리는지의 등록, 이 환경의 설정·상태, 운영 기록인가? → `30_Automations/`
6. 볼트 밖에서 도는 도구의 명세인가? → `40_Tools/`
7. 완료 조건이 있는 일에 속하는가? → `10_Projects/`
8. 그 외 → `50_Knowledge/`

## 5. 경계 판정 기준

- **볼트 규칙 vs 에이전트 규칙** — 볼트를 다스리면 `00_Vault/`, 에이전트의 볼트 밖 작업을 다스리면 `20_Agents/`. 볼트 규칙을 스킬로 전달할 때 본문은 `00_Vault/`, 스킬 파일은 `20_Agents/skills/` 에 둔다.
- **실행 자산 vs 배치** — 스크립트·프롬프트의 원본은 처음부터 `90_Shared/scripts/` 에 둔다 (단일 사용처여도 같다). `30_Automations/` 에는 그것을 트리거에 묶는 등록, 이 환경의 설정값, 상태 파일만 둔다. 무시 도메인에 원본을 두면 버전 관리도 백업도 되지 않는다.
- **자동화 vs 도구** — 트리거로 실행되면 `30_Automations/`, 사람이 보는 상시 화면·서버·CLI 면 `40_Tools/`. 도구의 기동 장치(launchd 등)는 인벤토리에 한 줄만 둔다.
- **공유 문서의 승격** — 규칙·참조 문서는 두 번째 도메인이 실제로 쓰기 시작할 때 `90_Shared/` 로 옮긴다.
- **지식의 승격** — 추적 문서(`20`·`40`·`90`)가 `50_Knowledge/` 의 노트를 인용해야 하면, 그 노트를 `90_Shared/references/` 로 올린다.
- **프로젝트 vs 지식** — 언제까지 무엇을 끝내는지는 `10_Projects/`, 무엇을 배웠는지는 `50_Knowledge/`. 프로젝트 이름을 지워도 뜻이 통하는 부분은 다른 프로젝트에서 처음 인용될 때 추출한다.

## 6. 폴더 공통 규칙

- **모든 폴더는 진입점 `_index.md` 를 갖는다** — 예외는 `Attachments/`, `폐기/`, 실행 자산만 담는 폴더(`scripts/` 등)다.
- **하위 폴더 승격** — 같은 주제의 노트가 3개를 넘으면 하위 폴더로 묶고 `_index.md` 를 만든다.
- **보관 구역은 없다** — 끝난 일은 제자리에서 `status: done` 으로 표시한다. 폐기 문서는 소속 폴더의 `폐기/` 로 옮기고 소속 `_index.md` 의 「폐기 문서」 절에서 가리킨다.
- **미분류 인박스와 날짜 폴더는 두지 않는다.**

## 7. 연결과 링크

- 그래프 루트는 [[_Home]] 이다. 모든 노트는 `_Home → 도메인 _index → (하위 _index) → 노트` 체인으로 도달 가능해야 한다.
- 루트 문서는 `_index` 체인에 넣지 않고 `_Home` 이 직접 가리킨다.
- 노트를 만들거나 옮기거나 폐기한 에이전트가 소속 `_index.md` 갱신까지 같은 작업에서 책임진다.
- **문서 → 문서는 위키링크만 쓴다** — 볼트 안의 파일을 볼트 안 다른 위치로 심볼릭링크하지 않는다. 같은 노트가 두 번 잡히고, 동기화·git 이 링크를 기대대로 옮기지 않는다.
- **실행기 → 볼트 자산은 실제 경로를 직접 가리킨다** — launchd 정의, 자동화 프롬프트는 `90_Shared/scripts/…` 를 쓴다.
- **볼트 밖에서 고정 경로가 필요하면 볼트 → 밖 방향 링크만 쓴다** — 링크는 밖(`~/.claude/skills/<skill>` 등)에 두고 실체는 볼트에 둔다.
- **스킬이 볼트 문서를 참조할 때는 볼트 루트 기준 경로로 적는다** — `../..` 같은 상대 경로는 쓰지 않는다.

## 8. 구조 변경

- 새 최상위 폴더는 이 규칙을 먼저 개정한 뒤에만 만든다. 개정은 사용자 승인을 받는다.
- 최상위 폴더를 추가·개명·폐지하면 같은 작업에서 [[_Home]] 과 [[AGENTS]] 의 도메인 표, `.gitignore`, 그래프 색상 그룹을 함께 고친다.
- 도메인 내부 구조의 변경은 그 도메인 `_index.md` 의 내부 규정 개정으로 한다. 이 규칙과 충돌하면 이 규칙이 우선한다.
