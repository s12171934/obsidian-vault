# 로컬 구성 규칙

> 볼트를 새로 받은 기계에서 서브모듈을 받고, 도구 스킬 디렉터리를 볼트 `20_Agents/skills/` 로 연결하는 절차를 정한다.
> 링크는 `00_Vault/scripts/link-skills.sh` 하나로 만든다. 연결 방식 자체는 [[스킬 로컬 연결 규칙]] 이 정한다.

## 1. 처음 구성하는 순서

1. 볼트를 서브모듈과 함께 받는다 — `git clone --recursive https://github.com/s12171934/obsidian-vault.git`
2. 무엇이 바뀔지 확인한다 — 볼트 루트에서 `00_Vault/scripts/link-skills.sh`
3. 확인한 내용으로 실행한다 — `00_Vault/scripts/link-skills.sh apply`
4. 로컬 전용 도메인(`10`·`30`·`50`)과 `CHANGE_LOG.md` 를 별도로 가져온다. `30_Automations/` 는 그 폴더의 비공개 저장소를 clone 한다.
5. Obsidian 으로 볼트를 열고, "제외된 파일"에 서브모듈의 `src/` · `node_modules/` · `vendor/` 를 넣는다.
6. 커밋 전 비밀 스캔(gitleaks pre-commit 훅)을 설치한다 ([[공개 저장소 규칙]]).

## 2. 스크립트가 하는 일

- **서브모듈** — 받지 않은 서브모듈이 있으면 `git submodule update --init --recursive` 를 실행한다.
- **디렉터리 링크** — 기본 대상 `~/.claude/skills` 를 `20_Agents/skills/` 로의 링크로 만든다.
    - 이미 실제 폴더가 있으면 지우지 않고 `<경로>.bak-<시각>` 으로 옮긴다.
    - 옛 폴더 안의 링크(외부 스킬 설치 도구가 만든 것)는 볼트 쪽에 같은 링크로 다시 만들고, 복사본 스킬은 볼트 쪽에 복사한다. 둘 다 git 무시 대상이다. 같은 이름이 볼트에 이미 있으면 볼트 쪽을 남긴다.
- **스킬별 링크** — 다른 프로그램이 관리하는 디렉터리(`~/.agents/skills`, `~/.codex/skills`, `~/.cursor/skills`, `~/.gemini/skills`, `~/.pi/agent/skills`, `~/.copilot/skills`, `~/.factory/skills`, Orca 의 Codex 계정 홈)에 내 스킬마다 링크를 만든다.
    - 없는 디렉터리는 건너뛴다 (그 도구를 쓰지 않는 기계).
    - 같은 이름의 실제 폴더가 있으면 건드리지 않고 알린다.
    - 볼트에서 사라진 스킬을 가리키는 링크는 지운다.
- 인자 없이 실행하면 바꿀 내용만 보여 주고, `apply` 를 주어야 실제로 바꾼다. 여러 번 실행해도 결과가 같다.

## 3. 대상 디렉터리 바꾸기

- 대상 목록의 기본값은 스크립트 맨 위에 있다. 기계마다 다르게 하려면 환경 변수로 덮어쓴다 (콜론으로 구분).
    - `VAULT_DIR_LINK_ROOTS` — 디렉터리째 링크할 경로
    - `VAULT_PER_SKILL_ROOTS` — 내 스킬만 스킬별로 링크할 경로
- 새 도구를 쓰게 되어 기본값을 바꾸면, 이 노트의 §2 목록도 같은 커밋에서 고친다.

## 4. 다시 실행하는 때

- 내 스킬 서브모듈을 추가·제거했을 때 — 스킬별 링크를 맞춘다.
- 새 도구를 설치해 그 스킬 디렉터리가 생겼을 때.
- 볼트 위치를 옮겼을 때 — 링크는 절대 경로라 다시 걸어야 한다.

## 5. 쓰기 경계

- 스크립트는 볼트 밖 디렉터리(홈 아래 도구 경로)를 바꾼다.
- 에이전트는 사용자가 지시했을 때 `apply` 를 실행한다. 확인 모드(인자 없음)는 언제든 실행할 수 있다.
- 예외 — 내 스킬 서브모듈을 추가·제거하는 작업에 따르는 재실행은 그 작업의 일부로 바로 한다.
