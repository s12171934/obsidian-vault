# 로컬 구성 규칙

> 볼트를 새로 받은 기계에서 볼트를 활성화하는 절차를 정한다 — 로컬 전용 도메인의 `_index.md` 생성, 서브모듈 받기, 도구 스킬 디렉터리 연결.
> 활성화는 `00_Vault/scripts/activate.sh` 하나로 한다. 스킬 연결 방식 자체는 [[스킬 로컬 연결 규칙]] 이 정한다.

## 1. 처음 구성하는 순서

1. 볼트를 서브모듈과 함께 받는다 — `git clone --recursive https://github.com/s12171934/obsidian-vault.git`
2. 무엇이 바뀔지 확인한다 — 볼트 루트에서 `00_Vault/scripts/activate.sh`
3. 확인한 내용으로 실행한다 — `00_Vault/scripts/activate.sh apply`
4. 로컬 전용 도메인(`10`·`30`·`50`)의 내용이 있으면 다른 기계에서 직접 복사해 온다. 이 도메인들은 git 으로 받지 않는다 ([[폴더 구조 규칙]] §2). 가져온 뒤 `activate.sh apply` 를 한 번 더 돌려 「규칙」을 맞춘다.
5. Obsidian 으로 볼트를 열고, "제외된 파일"에 서브모듈의 `src/` · `node_modules/` · `vendor/` 를 넣는다.
6. 커밋 전 비밀 스캔(gitleaks pre-commit 훅)을 설치한다 ([[공개 저장소 규칙]]).
7. 첨부 업로드를 구성한다 — Obsidian 설정의 "새 첨부 파일을 만들 위치"를 `Attachments/` 로 두고, 업로더 플러그인(S3 Image Sync)을 설치해 버킷 한정 R2 자격증명을 넣는다. 설정값은 로컬 노트 `30_Automations/첨부 R2/첨부 R2 설정.md`, 규칙은 [[첨부 규칙]]. 확인 — `00_Vault/scripts/r2_sync.py plan`.

## 2. 스크립트가 하는 일

- **로컬 인덱스** (`local_index.py`) — `10_Projects` · `30_Automations` · `50_Knowledge` 마다
    - `_index.md` 가 없으면 최소 형태로 만든다. 요약은 [[폴더 구조 규칙]] §2 표의 「담는 것」 칸에서 가져온다.
    - 「규칙」 절을 그 도메인 `rules/` 의 노트 목록으로 다시 쓴다 (`- [[제목]] — 요약 첫 문장`). 「목록」 등 다른 절은 그대로 둔다.
    - `CHANGE_LOG.md` 가 없으면 빈 로그로 만든다.
- **프로젝트 진행** (`local_index.py`) — `10_Projects/<프로젝트>/` 에 `일정/` 과 스테이지 폴더(`<no> <이름>/`)가 있으면
    - 스텝 노트(`일정/<키> S.TT <스텝>.md`)의 코드 `S` 로 스테이지를, 프론트매터에서 `status`·`date`·`endDate` 를 읽는다. `<키>` 는 프로젝트 폴더 이름의 첫 단어다.
    - 번호 붙은 문서를 검사한다 — 정식 문서 `<키> S.TT.NNN` 은 스테이지 폴더(S=0 은 루트), 로그 `<키> S.TT.LNNN … YYYY-MM-DD` 는 `기록/` 에 있는지, 번호 중복, 스텝 노트가 없는 `S.TT`, `type/기록` 과 폴더의 일치.
    - `<프로젝트> 타임라인.md` 가 있으면 「타임라인」 절을 스텝 표로 다시 쓴다 (다른 절은 그대로).
    - `progress.json` 을 agent-dashboard 의 `exports/project-progress.schema.json` 형식으로 쓴다 — 스테이지와 스텝만, 파생값 없이.
- **태그 검사** — `type/` 값이 등록 목록에 있는지, 모든 노트에 `agent/` 태그가 정확히 하나 있고 등록된 접두사를 쓰는지 확인한다 (알리기만 한다).
    - 지식 분류표가 없으면 [[노트 작성 규칙]] §3 의 대분류 목록으로 골격을 만든다.
    - 지식 분류 검사 — `50_Knowledge/` 의 폴더·문서 번호·`title` 이 로컬 지식 분류표(`50_Knowledge/지식 분류표.md`)와 맞는지, 볼트 전체의 `domain/`·`area/`·`topic/` 태그가 등록되어 있고 상위 태그를 함께 갖는지 확인한다. 어긋나면 `!` 로 알리고, `apply` 하면 50 문서의 분류 태그를 번호에 맞춰 고친다.
- **서브모듈** — 받지 않은 서브모듈이 있으면 `git submodule update --init --recursive` 를 실행한다.
- **디렉터리 링크** — 기본 대상 `~/.claude/skills` 를 `20_Agents/skills/` 로의 링크로 만든다.
    - 이미 실제 폴더가 있으면 지우지 않고 `<경로>.bak-<시각>` 으로 옮긴다.
    - 옛 폴더 안의 링크(외부 스킬 설치 도구가 만든 것)는 볼트 쪽에 대상의 절대 경로로 다시 만들고, 복사본 스킬은 볼트 쪽에 복사한다. 둘 다 git 무시 대상이다. 같은 이름이 볼트에 이미 있으면 볼트 쪽을 남긴다.
    - 대상이 없는 링크는 다시 만들지 않고 백업에 남긴다.
- **스킬별 링크** — 다른 프로그램이 관리하는 디렉터리(`~/.agents/skills`, `~/.codex/skills`, `~/.cursor/skills`, `~/.gemini/skills`, `~/.pi/agent/skills`, `~/.copilot/skills`, `~/.factory/skills`, Orca 의 Codex 계정 홈)에 내 스킬마다 링크를 만든다.
    - 없는 디렉터리는 건너뛴다 (그 도구를 쓰지 않는 기계).
    - 같은 이름의 실제 폴더가 있으면 건드리지 않고 알린다.
    - 볼트에서 사라진 스킬을 가리키는 링크는 지운다.
- 인자 없이 실행하면 바꿀 내용만 보여 주고, `apply` 를 주어야 실제로 바꾼다. 여러 번 실행해도 결과가 같다.

## 3. 대상 디렉터리 바꾸기

- 대상 목록의 기본값은 스크립트 맨 위에 있다. 기계마다 다르게 하려면 환경 변수로 덮어쓴다 (콜론으로 구분).
    - `VAULT_DIR_LINK_ROOTS` — 디렉터리째 링크할 경로
    - `VAULT_PER_SKILL_ROOTS` — 내 스킬만 스킬별로 링크할 경로
- 새 도구를 쓰게 되어 기본값을 바꾸면, 이 노트의 §2 목록도 같은 커밋에서 고친다.

## 4. 다시 실행하는 때

- 로컬 전용 도메인의 `rules/` 를 추가·변경했거나 `git pull` 로 받았을 때 — 로컬 `_index.md` 의 「규칙」을 맞춘다.
- 내 스킬 서브모듈을 추가·제거했을 때 — 스킬별 링크를 맞춘다.
- 새 도구를 설치해 그 스킬 디렉터리가 생겼을 때.
- 볼트 위치를 옮겼을 때 — 링크는 절대 경로라 다시 걸어야 한다.

## 5. 쓰기 경계

- `local_index.py` 는 볼트 안의 로컬 노트만 바꾼다. 에이전트는 언제든 `apply` 할 수 있다.
- `link-skills.sh`(그리고 그것을 부르는 `activate.sh`)는 볼트 밖 디렉터리(홈 아래 도구 경로)를 바꾼다. 에이전트는 사용자가 지시했을 때 `apply` 를 실행한다. 확인 모드(인자 없음)는 언제든 실행할 수 있다.
- 예외 — 내 스킬 서브모듈을 추가·제거하는 작업에 따르는 재실행은 그 작업의 일부로 바로 한다.
