# 노트 작성 규칙

> 볼트 노트의 프론트매터, 파일명, 태그, 링크, 본문 형식을 정하는 강제 규칙이다. 독자는 AI 에이전트다.
> 목표는 grep·프론트매터 쿼리·링크 추적만으로 노트를 찾고, 노트 하나만 읽어도 파싱할 수 있게 하는 것이다.
> 노트를 언제 나누는지는 [[노트 분할 규칙]], 첨부 표기는 [[첨부 규칙]], 이력은 [[변경 이력 규칙]] 이 정한다.

## 1. 적용 범위와 프론트매터

- 볼트의 모든 `.md` 노트에 적용한다. 예외는 아래뿐이다.
    - 루트 `CLAUDE.md` — 도구가 읽는 포인터 파일이다.
    - 서브모듈의 `SKILL.md` — 에이전트 도구가 형식을 정한다. 내 서브모듈(`s12171934` 공개 저장소)의 다른 `.md` 는 이 규칙을 따르고, `README.md` 의 `title` 은 저장소 이름으로 쓴다.
    - 기계가 직접 읽는 비노트 파일(스크립트, JSON 상태, plist, 프롬프트 원문) — 프론트매터와 한국어 파일명 규칙의 예외다. 프론트매터 없이 기계 입력으로 쓰는 Markdown 은 `.md` 대신 `.txt` 로 두어 노트와 구분한다.

```yaml
---
title: 노트 제목        # 필수. 파일명과 같다
created: 2026-10-16    # 필수. YYYY-MM-DD
updated: 2026-10-16    # 필수. 내용이 바뀔 때마다 갱신
tags: [domain/소프트웨어설계, area/디자인패턴, type/조사, agent/claude-<세션 ID>]  # 필수. §3 의 등록된 축만
source: ai             # 필수. ai | external (외부 자료 스크랩)
status: active         # 프로젝트·설계 문서: draft | active | done. 일정 노트(스텝): scheduling | pending | active | done | failed
date: 2026-10-16       # 일정 노트(type/일정)만 — 시작일·발생일. status 가 scheduling 이면 두지 않는다
endDate: 2026-10-20    # 기간형 일정 노트만 — 종료일. 진행 중이면 최신 진행일
---
```

- 필드 추가는 이 스키마를 먼저 개정한 뒤에만 한다. 미등록 필드는 쓰지 않는다.
- `updated` 는 AI 의 신선도 판단 기준이다. 노트가 말하는 내용을 바꾸면 반드시 갱신한다.
- 사람이 채팅으로 구술한 내용도 `source: ai` 로 기록하고, 본문에 누구의 판단·지시인지 밝힌다.

## 2. 파일명

- 파일명 = `title`. 한국어 자연어 명사구로 쓴다. 예: `삭제 트랜잭션 이층화.md`
- 폴더 진입점은 `_index.md` 다. `title` 은 `<폴더명> 인덱스` 로 쓴다 (프로젝트 폴더는 프로젝트 이름).
- 날짜·번호 접두사를 붙이지 않는다. 날짜가 식별자인 정형 노트(일자 리포트 등)는 날짜를 끝에 둔다.
    - 예외 — `50_Knowledge/` 의 문서는 분류 번호 `D.AA.SS.NNN` 을 앞에 둔다 (`3.01.01.007 코디네이터 호출 규율.md`). 번호 체계와 배치는 [[50_Knowledge 범위 규칙]] 이 정한다.
- 프로젝트 코드·이슈 키(`ABC-12 …`)는 검색 키이므로 앞에 둘 수 있다.
- 금지 문자: `/ \ : * ? " < > | # ^ [ ]`
- 개명은 Obsidian 안에서 한다 (링크 자동 갱신). 파일시스템에서 직접 옮겼으면 백링크를 grep 으로 찾아 고친다.

## 3. 태그

- 모든 분류는 프론트매터 `tags:` 에만 둔다. 본문 인라인 태그(`#단어`)는 쓰지 않는다.

| 축 | 예 | 용도 |
| --- | --- | --- |
| `domain/<대분류>` | `domain/소프트웨어설계` | 장기간 유지되는 최상위 영역. 내용 노트에 최소 1개 |
| `area/<중분류>` | `area/디자인패턴` | 대분류 안에서 여러 노트가 공유하는 하위 분야 |
| `topic/<소분류>` | `topic/프로토타입패턴` | 노트가 직접 다루는 구체적인 기술·패턴·문제 |
| `project/<slug>` | `project/abc-12` | 도메인을 가로지르는 프로젝트 소속 |
| `type/<종류>` | `type/조사` `type/기록` | 작업 성격. 아래 등록 목록의 값만 |
| `agent/<도구>-<세션 ID>` | `agent/claude-<세션 ID>` | 노트를 처음 만든 에이전트 세션. 모든 노트에 정확히 1개 |
| `status/미결` | | 후속 조치가 남음. 처리 후 즉시 제거 |
| `meta` | | `00_Vault/` 문서와 루트 진입 문서 |

- **상위 포함** — `topic/` 을 쓰면 부모 `area/`·`domain/` 을, `area/` 를 쓰면 `domain/` 을 함께 둔다.
- **최소 깊이** — 인덱스·규칙 문서를 뺀 내용 노트는 `domain/` + `area/` 를 갖는다.
- **인덱스의 깊이** — 인덱스는 소속 노트 전체에 공통인 단계까지만 붙인다.
- **소분류 효용** — `topic/` 은 두 노트 이상을 하나의 검색 결과로 묶을 때만 만든다. 제목·날짜·버전·티켓 번호·일회성 표현은 `topic/` 으로 만들지 않는다.
- **중복 금지** — 상·하위 태그가 늘 같은 노트 집합을 가리키면 자연스러운 한 단계만 남긴다.
- **분류표 등록** — `area/`·`topic/` 은 지식 분류표(로컬 노트 `50_Knowledge/지식 분류표.md`, [[50_Knowledge 범위 규칙]])에 코드와 함께 등록된 것만 쓴다. 새로 필요하면 등록된 항목에서 동의어를 먼저 찾고, 없을 때만 분류표에 등록한 뒤 쓴다. 태그 이름은 볼트 전체에서 유일하며 부모 하나에만 속한다.
- **작업 성격 (`type/`)** — 등록된 값: `조사` · `결정` · `설계` · `회의록` · `발표` · `검증` · `보고서` · `절차` · `회고` · `일정` · `기록`. 내용 노트는 하나를 단다. 진행 단계와 무관한 공용 분류이며, 새 값은 이 목록을 먼저 개정한다.
- **로그 문서와 정식 문서** — 에이전트가 남기는 단순 로그(작업·진행 로그, 커밋 정리, 리뷰 라운드 기록, 세션 인계, 실측 결과)는 `type/기록` 이다. 시점 스냅숏이라 고쳐 쓰지 않고 덧붙이며, CHANGE_LOG 를 면제한다 ([[변경 이력 규칙]] §5). 그 밖의 노트는 정식 문서로, 현재 상태를 유지하고 이 규칙을 모두 따른다. 로그에서 나온 결론은 정식 문서로 옮긴다.
- **생성 세션 (`agent/`)** — 값은 `<도구>-<세션 전체 ID>` 다. 등록된 도구 접두사: `claude`(`CLAUDE_CODE_SESSION_ID`) · `codex`(`CODEX_THREAD_ID`). 노트를 만들 때 환경 변수에서 읽고, 없으면 사용자에게 묻는다. 노트를 처음 만든 세션 하나만 달고, 다른 세션이 고쳐도 바꾸지 않는다. 만든 세션을 확인할 수 없는 기존 노트는 `agent/미상` 이다. 스크립트가 만든 노트는 스크립트를 실행한 세션을 단다. 이 축은 일회성 값이지만 등록 축이다 (소분류 효용 규칙의 예외). 새 도구는 접두사를 먼저 등록한다.
- 계층은 1단까지. 한국어는 붙여쓰기, 영문은 소문자 케밥케이스. 폴더로 이미 알 수 있는 정보는 태그로 중복하지 않는다.
- 등록된 대분류는 50 분류 번호의 대분류 코드와 1:1 이다 (이 목록이 원본이고, 분류표의 대분류 행은 이를 따른다): `domain/지식관리`(0) · `domain/소프트웨어설계`(1) · `domain/소프트웨어구현`(2) · `domain/인공지능`(3) · `domain/자동화`(4) · `domain/금융경제`(5) · `domain/교육`(6) · `domain/커리어`(7) · `domain/문화`(8). 9 는 예비다. 새 대분류는 이 목록을 먼저 개정해 예비 자리에 넣고 분류표에 행을 더하며, 새 축은 이 절을 먼저 개정한다.

## 4. 링크

- 다른 노트를 언급하면 `[[위키링크]]` 로 건다.
- `_index.md`·`README.md` 처럼 파일명이 겹치는 노트는 전체 경로 + 별칭으로 링크한다 — `[[10_Projects/_index|10_Projects]]`.
- **암묵 참조 금지** — "위 문서", "지난번 결정", "해당 이슈" 대신 `[[노트]]` 나 명시적 식별자(`ABC-12`)를 쓴다.
- **외부 링크는 라벨 필수** — `[ABC-12 (이슈 트래커)](https://…)`. 벌거벗은 URL 은 쓰지 않는다.
- **섹션 링크 금지** — `[[노트#섹션]]` 은 깨지기 쉽다. 가리키고 싶은 섹션은 노트로 승격한다 ([[노트 분할 규칙]]). 예외는 로컬 노트의 `CHANGE_LOG` 포인터 하나다.
- **미작성 노트 링크** — 로컬 도메인(`10`·`30`·`50`)에서는 미작성 노트에도 링크를 먼저 걸 수 있다 (미해결 링크 = 작성 후보). 추적 문서에는 미해결 링크를 남기지 않는다.
- 추적 문서가 링크를 걸 수 있는 범위는 [[폴더 구조 규칙]] §3 이 정한다.

## 5. 본문 구조

- **첫 요소는 `>` 인용 블록 요약** — 1~3문장, 최대 5줄. 이 노트가 무엇이고 왜 있는지를 노트 단독으로 읽히게 쓴다.
- **요약에 경위를 쌓지 않는다** — 개정 이유, 검수 반영 내역은 이력으로 보낸다. 요약은 현재 상태만 말한다.
- **본문은 불릿으로 쓴다** — 요약 아래는 문단형 서술 대신 `-` 목록으로 쓴다. 예외는 코드 블록과 표다. 순서가 의미를 갖는 절차는 번호 목록(`1.`)을 쓴다.
- **한 불릿 = 한 가지 사실** — 사실·이유·예외를 한 항목에 겹치지 않는다. 두 문장을 넘으면 나누거나 하위 불릿으로 내린다.
- **문장은 짧게 끊는다** — 항목 이름과 설명은 대시(`—`)로 구분해 앞부분만 읽어도 무엇에 대한 항목인지 알게 한다.
- 불릿 중첩은 2단까지. 3단이 필요하면 헤더를 추가하거나 노트를 나눈다.
- 헤더는 `##` 부터, 계층을 건너뛰지 않는다. 내용 없는 헤더를 미리 만들지 않는다.
- 확정 사항은 `## 결정` 섹션에 `- YYYY-MM-DD — 내용` 으로 쌓는다. 본문에 흘려 쓰지 않는다.
- 남은 일은 `## 미결` 에 적고 프론트매터에 `status/미결` 태그를 단다.
- 코드·경로·식별자·테이블명은 백틱으로 감싼다 — `deleted_at`, `orders`.
- 표는 짧은 열거 사실에만 쓴다. 조건·인과가 있는 내용은 문장으로 쓴다.
- 체크박스(`- [ ]`)는 실행할 작업에만 쓴다.
- 사람만 이해하는 표현을 쓰지 않는다 — 이모지 의미(🟢=승인 등), 색·위치에 기대는 서술("아래 빨간 부분").

## 6. 하지 않는 것

- **같은 사실의 복제** — 링크로 대체한다. 복제가 불가피하면 한쪽에 `SSOT: [[원본]]` 을 적는다.
- **깊은 폴더 중첩** — 도메인 폴더 아래 3단을 넘기지 않는다. 더 깊은 구조가 필요하면 그 도메인 `rules/` 의 규칙 노트에 근거를 두고 예외를 정한다.
- **특정 도구 전용 문법** — 표준 마크다운 + Obsidian 위키링크·프론트매터까지만 쓴다 (Dataview 쿼리, 도구별 확장 블록 금지).
    - 예외: Obsidian Bases 의 `.base` 뷰 파일은 파생 뷰로 허용한다. 정보의 원본은 항상 노트에 있어야 하고, `.base` 를 지워도 정보가 사라지지 않아야 한다. `.base` 도 소속 `_index.md` 에 등록한다.
- **프론트매터 없는 노트** — §1 의 예외가 아니면 두지 않는다.
- **추적 문서의 공개 금지 항목** — 비밀·식별자·개인정보·회사 내부 정보 ([[공개 저장소 규칙]]).
