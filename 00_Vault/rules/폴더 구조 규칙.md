# 폴더 구조 규칙

> 볼트의 최상위 폴더 구성, git 추적 경계와 도메인 사이의 의존 방향, 서브모듈의 공개 면, 새 노트·자산을 어느 폴더에 둘지 판정하는 규칙이다.
> 최상위 폴더 하나는 도메인 하나다. 각 도메인 안의 세부 규칙은 그 도메인 `rules/` 의 규칙 노트가 정한다.

## 1. 원칙

- **도메인 = 최상위 폴더** — 노트가 어느 도메인에 속하는지가 곧 위치다.
- **도메인이 아닌 최상위는 첨부 버퍼(`Attachments/`) 하나뿐이다.**
- **이름은 역할로 짓는다** — 도구·제품 이름(Orca, Obsidian, 특정 스킬 등)을 폴더 이름에 넣지 않는다.
- **번호는 10 단위다** — 새 도메인은 비어 있는 60·70·80·90 을 쓴다.
- **사람은 볼트에 직접 쓰지 않는다** — 사람의 입력은 에이전트 세션(채팅)으로 받고, 에이전트가 해당 도메인에 노트로 남긴다.
- **실행 근거는 그것을 정의한 쪽이 소유한다** — 공유를 위한 별도 부품 구역은 두지 않는다. 다른 쪽은 공개 면(§4)으로 의존한다.

## 2. 최상위 구성

| 폴더 | 종류 | git | 담는 것 |
| --- | --- | --- | --- |
| `00_Vault/` | 도메인 | 추적 | 볼트 자체를 다스리는 규칙(`rules/`), 템플릿, 볼트 구성 스크립트(`scripts/`) |
| `10_Projects/` | 도메인 | 무시 (`rules/` 는 추적) | 완료 조건이 있는 일 |
| `20_Agents/` | 도메인 | 추적 (`skills/` 아래는 내 스킬 서브모듈만) | 에이전트 행동 정의 — 로컬 스킬 목록의 원본 |
| `30_Automations/` | 도메인 | 무시 (`rules/` 는 추적) | 자동화 배치 등록부와 30 전용 자산 — 별도 비공개 저장소 |
| `40_Tools/` | 도메인 | 추적 | 도구 저장소(코드 + 명세) — 도구별 서브모듈 |
| `50_Knowledge/` | 도메인 | 무시 (`rules/` 는 추적) | 학습·참고 지식 |
| `Attachments/` | 기반 | 무시 | R2 업로드 전 첨부의 임시 버퍼 |

- 루트에는 `AGENTS.md` · `CLAUDE.md` · `_Home.md`(추적)와 `CHANGE_LOG.md`(무시)만 둔다. `.gitignore` · `.gitmodules` 는 저장소 설정 파일이라 예외다.
- 추적 대상과 서브모듈은 공개 저장소에 올라간다. 넣을 수 있는 내용은 [[공개 저장소 규칙]] 이 정한다.
- **로컬 전용 도메인의 `rules/` 는 추적한다** — 규칙은 어느 기계에서나 같아야 하기 때문이다. 나머지 내용과 `_index.md` 는 무시하며, `_index.md` 는 볼트를 활성화할 때 스크립트가 `rules/` 로부터 만든다 ([[로컬 구성 규칙]]).
    - 추적되는 `rules/` 노트도 추적 문서다. 같은 도메인의 무시 대상 노트로 위키링크를 걸지 않고 백틱 경로로만 언급한다.
- `30_Automations/` 는 독립 비공개 저장소로 버전 관리한다 (서브모듈이 아니다). 볼트 저장소가 `30_Automations/rules/` 를 추적하므로 그 폴더 안에 `.git` 을 두지 않고, 별도 git 디렉터리를 쓴다 (`git --git-dir=<볼트 밖 경로> --work-tree=30_Automations`). 그 저장소는 `rules/` 를 무시한다.

## 3. 추적 경계와 의존 방향

- **추적 = 정의, 무시 = 인스턴스·기록** — 추적 도메인은 다른 기계·볼트에서도 그대로 쓸 수 있는 정의다. 무시 도메인은 이 환경에서 무엇을 돌리고, 무엇을 했고, 무엇을 알게 되었는지다.

| 소비 → 대상 | 허용 | 수단 |
| --- | --- | --- |
| `30` → `20` | 허용 | 스킬 이름 호출, `exports/` 경로 |
| `30` → `40` | 허용 | `bin/` CLI 실행, `exports/` 경로 |
| `20` → `40` | 허용 | `bin/` CLI 실행만. 스킬 본문에 도구 설치를 전제 조건으로 적는다 |
| `20` → `20` | 허용 | 스킬 이름으로만. 공용 규칙은 규칙 전용 스킬로 만든다 |
| `40` → `20` | **금지** | 도구가 스킬의 규칙을 필요로 하면 그 규칙의 주인을 도구로 옮긴다 |
| `20`·`40` → `30` | **금지** | 누구도 배치 등록부를 참조하지 않는다 |

- **파일 공유는 최후 수단이다** — 실행 인터페이스(CLI·스킬 이름)로 풀리지 않을 때만 주인 저장소의 `exports/` 에서 복사(vendor)하고, 복사본 첫 줄에 원본 저장소·경로·커밋을 적는다.
- **추적 문서는 clone 직후 비어 있을 수 있는 곳으로 위키링크를 걸지 않는다** — 무시 도메인과 서브모듈 내부가 해당한다. 그런 곳은 백틱 경로 관례로만 언급한다.
- **볼트 링크 예외** — 연결 체인을 유지하기 위해 아래 두 곳만 허용한다. 둘 다 「clone 환경에서는 비어 있을 수 있다」는 사실을 그 절의 요약 인용문에 적는다.
    - [[_Home]] 의 「로컬 전용 도메인」 절 → 무시 도메인의 `_index.md`
    - `20_Agents/_index.md` · `40_Tools/_index.md` 의 「목록」 절 → 각 서브모듈의 `README.md` (서브모듈을 받지 않고 clone 하면 비어 있다)

## 4. 서브모듈과 공개 면

- 내 스킬(`20_Agents/skills/<skill>/`)과 도구(`40_Tools/<tool>/`)는 각각 독립 공개 저장소이며 볼트에는 서브모듈로 들어온다. 외부에서 단독으로 clone 해도 완결되어야 한다. 외부·로컬 전용 스킬의 형태는 [[스킬 출처 관리 규칙]] 이 정한다.
- **공개 면** — 저장소 밖에서 참조해도 되는 것은 아래뿐이다. 나머지는 내부 전용이라 예고 없이 바뀔 수 있다.
    - 스킬: 스킬 이름, `exports/` (목록과 용도는 `exports/EXPORTS.md`)
    - 도구: `bin/` CLI 진입점, `exports/` (스키마·프롬프트 등)
- 내부 전용 — 스킬의 `references/`, 도구의 `src/` 와 그 밖의 파일.
- **버전 고정은 볼트 저장소의 서브모듈 포인터가 한다** — 포인터를 올리는 커밋이 곧 소비자(30 등)의 의존성 업그레이드다.
- **의존 검사** — `30_Automations` 인벤토리의 「의존」 열에 쓰는 공개 면 경로를 적고, 서브모듈 포인터를 올릴 때마다 그 경로가 남아 있는지 확인한다.
- **README 필수** — 모든 서브모듈은 루트에 `README.md` 를 둔다. 목적, 설치·기동 방법, 공개 면 요약을 담고, 볼트에서 그 서브모듈로 들어가는 유일한 진입점이 된다.
- **서브모듈 안 노트 연결** — 서브모듈의 모든 `.md` 는 `README.md` 에서 위키링크를 따라 도달할 수 있어야 한다. 끊긴 노트를 두지 않는다.
    - `README.md` 는 `SKILL.md` 와, 문서 묶음이 있으면 그 노트들(또는 묶음의 진입 노트)을 위키링크한다.
    - 서브모듈마다 겹치는 파일명(`SKILL.md` · `README.md`)은 볼트 기준 전체 경로 + 별칭으로 건다 — `[[20_Agents/skills/<skill>/SKILL|SKILL.md]]`. 서브모듈 경로는 이 규칙이 고정하므로 경로가 흔들리지 않는다.
- **`SKILL.md` 에는 Obsidian 위키링크를 쓰지 않는다** — 에이전트 도구가 읽는 파일이라 위키링크가 해석되지 않는다. 다른 스킬은 스킬 이름으로, 자기 저장소의 파일은 백틱 상대 경로(`references/<파일>.md`)로 가리킨다.
- 서브모듈 안을 고치는 것은 볼트 내부 쓰기이고, 각 서브모듈 저장소로 push 하는 것은 외부 쓰기다.

## 5. 배치 판정 순서

위에서부터 묻고, 처음 해당하는 곳에 둔다.

1. 외부 도구가 파일의 형식이나 위치를 강제하는가? → 그 위치 (루트 진입 문서, `SKILL.md`, `Attachments/`)
2. 볼트 자체(노트 작성·폴더·링크·태그·이력)를 다스리는 규칙인가? → `00_Vault/`
3. 에이전트의 행동을 정하는 스킬이나 그 실행 근거인가? → `20_Agents/skills/<skill>/`
4. 볼트 밖에서 도는 도구의 코드·명세인가? → `40_Tools/<tool>/`
5. 트리거로 무엇을 언제 돌리는지의 등록, 이 환경의 설정·상태, 30 에서만 쓰는 스크립트·프롬프트, 운영 기록인가? → `30_Automations/`
6. 완료 조건이 있는 일에 속하는가? → `10_Projects/`
7. 그 외 → `50_Knowledge/`

## 6. 경계 판정 기준

- **볼트 규칙 vs 에이전트 규칙** — 볼트를 다스리면 `00_Vault/`, 에이전트의 볼트 밖 작업을 다스리면 `20_Agents/`. 볼트 규칙을 스킬로 전달할 때 본문은 `00_Vault/`, 스킬은 본문을 가리키는 전달 수단이다.
- **자동화 vs 도구** — 트리거로 실행되면 `30_Automations/`, 사람이 보는 상시 화면·서버·CLI 면 `40_Tools/`. 도구의 기동 장치(launchd 등)는 인벤토리에 한 줄만 둔다.
- **스킬·도구 소유 vs 30 전용** — 스킬이나 도구가 쓰거나 외부에 내보낼 가치가 있으면 그 저장소가 소유한다. 이 환경에 맞춘 스크립트·프롬프트는 `30_Automations/` 가 소유한다.
- **지식의 승격** — 스킬·도구가 `50_Knowledge/` 의 노트를 근거로 써야 하면, 그 노트를 해당 저장소의 `references/`(내부) 또는 `exports/`(공개)로 옮긴다.
- **프로젝트 vs 지식** — 언제까지 무엇을 끝내는지는 `10_Projects/`, 무엇을 배웠는지는 `50_Knowledge/`. 프로젝트 이름을 지워도 뜻이 통하는 부분은 다른 프로젝트에서 처음 인용될 때 추출한다.

## 7. 폴더 공통·연결·링크

- **볼트 폴더는 진입점 `_index.md` 를 갖는다** — 예외는 `Attachments/`, `폐기/`, `rules/`, `scripts/` 처럼 실행 자산만 담는 폴더, `20_Agents/skills/`(도구가 하위 폴더를 스킬로 읽는다), 서브모듈 내부다.
- **`_index.md` 는 최소 단위로 쓴다** — 요약 인용문(무엇을 담는 폴더인지 1~2줄), `상위:` 링크, 「규칙」(그 폴더 `rules/` 의 규칙 노트 목록), 「목록」(하위 폴더·노트) 만 둔다. 내용이 없는 절은 두지 않는다. 범위·제약·절차는 `_index.md` 에 쓰지 않고 규칙 노트로 둔다.
- **규칙은 `rules/` 의 노트로 추가한다** — 도메인(또는 하위 폴더)의 규칙은 그 폴더의 `rules/<규칙 이름>.md` 에 노트 하나로 두고, 같은 폴더 `_index.md` 의 「규칙」이 가리킨다. 규칙 노트 이름은 볼트 전체에서 겹치지 않게 짓는다 (도메인 범위 규칙은 `<도메인> 범위 규칙`). 서브모듈은 자기 저장소 규칙을 따르고, 진입점은 `_index.md` 대신 루트 `README.md` 다.
- **서브모듈 연결** — 소속 도메인 `_index.md` 의 「목록」이 서브모듈마다 한 줄로 `README.md` 를 위키링크한다. `README.md` 는 파일명이 겹치므로 전체 경로 + 별칭으로 쓴다 — `[[40_Tools/agent-dashboard/README|agent-dashboard]]`. 도달 체인은 `_Home → 도메인 _index → README.md` 다.
- `README.md` 는 Obsidian "제외된 파일"에 넣지 않는다.
- **하위 폴더 승격** — 같은 주제의 노트가 3개를 넘으면 하위 폴더로 묶고 `_index.md` 를 만든다.
- **보관 구역·미분류 인박스·날짜 폴더는 두지 않는다** — 끝난 일은 제자리에서 `status: done`, 폐기 문서는 소속 폴더의 `폐기/` 로 옮기고 소속 `_index.md` 의 「폐기 문서」 절에서 가리킨다.
- 그래프 루트는 [[_Home]] 이다. 모든 노트는 `_Home → 도메인 _index → (하위 _index) → 노트` 체인으로 도달 가능해야 하며, 노트를 만들거나 옮긴 에이전트가 `_index.md` 갱신까지 책임진다.
- **문서 → 문서는 위키링크만 쓴다** — 볼트 안의 파일을 볼트 안 다른 위치로 심볼릭링크하지 않는다.
- **볼트 안에서 밖을 가리키는 링크를 두지 않는다** — 예외는 외부 스킬 설치 도구가 `20_Agents/skills/` 에 만드는 링크 하나다. 이 링크는 git 무시 대상이라 공개 저장소에 올라가지 않는다.
- **볼트 밖에서 고정 경로가 필요하면 볼트 → 밖 방향 링크만 쓴다** — 도구 스킬 디렉터리는 `20_Agents/skills/` 로 디렉터리째 링크하거나, 다른 프로그램이 관리하는 디렉터리면 내 스킬만 스킬별로 링크한다. 복사하지 않는다 ([[스킬 로컬 연결 규칙]], 절차는 [[로컬 구성 규칙]]).
- **Obsidian 노출 제외** — 설정의 "제외된 파일"에 서브모듈의 `src/` · `node_modules/` · `vendor/` 를 넣는다. 도구 저장소는 `docs/` 만 볼트 노트로 보이게 한다.

## 8. 구조 변경

- 새 최상위 폴더는 이 규칙을 먼저 개정한 뒤에만 만든다. 개정은 사용자 승인을 받는다.
- 최상위 폴더를 추가·개명·폐지하면 같은 작업에서 [[_Home]] 과 [[AGENTS]] 의 도메인 표, `.gitignore`, 그래프 색상 그룹을 함께 고친다.
- 서브모듈을 추가·제거하면 `.gitmodules` 와 소속 도메인 `_index.md` 의 목록을 같은 작업에서 고친다.
- 도메인 내부 구조의 변경은 그 도메인 `rules/` 의 규칙 노트를 추가·개정해서 한다. 이 규칙과 충돌하면 이 규칙이 우선한다.
