# 공개 저장소 규칙

> git 추적 대상(`00_Vault` · 루트 진입 문서 · `10`·`30`·`50` 의 `rules/`)과 서브모듈 저장소(`20_Agents/skills/*` · `40_Tools/*`)는 공개 저장소에 올라간다. 이 노트는 추적 문서에 넣지 말아야 할 내용과, 그 사고를 막는 장치를 정한다.
> 추적 범위 자체는 [[폴더 구조 규칙]] §2 가 정한다.

## 1. 추적 문서에 넣지 않는 것

| 항목 | 대신 둘 곳 |
| --- | --- |
| 토큰·API 키·쿠키·인증서·비밀번호 | 키체인 등 비밀 저장소. 문서에는 항목 이름만 적는다 |
| 계정·채널·봇·서버 식별자, 이메일, 실명 | `30_Automations/` 의 환경 설정 |
| 홈 절대 경로 (`/Users/<이름>/…`) | `~/…` 또는 `<vault>/…` 자리표시 |
| 회사 내부 정보 — 사내 티켓 키, 제품·고객 이름, 내부 시스템 구조 | `10_Projects/` |
| 개인 일정·건강·금융 등 사생활 정보 | 무시 도메인 |

- 스크립트는 위 값을 코드에 박지 않고 환경 변수·설정 파일·키체인에서 읽는다. 그 설정 파일은 무시 도메인에 둔다.
- 예시가 필요하면 자리표시(`<channel-id>`, `example.com`)를 쓴다.

## 2. 무시 대상 고정

- `.obsidian/` 은 통째로 무시한다. 플러그인 `data.json` 에 자격증명이 들어갈 수 있다.
- `Attachments/` 는 무시한다. 업로드 전 임시 버퍼다.
- `30_Automations/` 는 볼트 저장소에서 무시하고, 그 폴더의 독립 저장소는 반드시 **비공개** 원격을 쓴다.
- 서브모듈 저장소도 각자 `.gitignore` 와 커밋 전 점검을 갖춘다. 볼트 저장소의 점검은 서브모듈 내용을 검사하지 않는다.
- 무시 목록의 원본은 루트 `.gitignore` 다. 최상위 구성이 바뀌면 같은 작업에서 고친다.

## 3. 추적 대상 추가는 사용자 확인이 먼저

- 커밋 대상에 새 파일이 들어가게 되는 작업은 파일을 만들기 전에 사용자에게 묻는다. 예: `rules/` 에 규칙 노트 추가, `00_Vault/` · 루트에 문서 추가, 서브모듈 추가, 무시하던 파일을 추적으로 전환.
- 물을 때는 위치·파일 이름·추적 여부를 제시하고, 무시 도메인(로컬)에 두는 대안을 함께 낸다. 규칙·정의가 아니라 이 환경의 등록부·기록이면 로컬이 기본이다 ([[폴더 구조 규칙]] §3 "추적 = 정의, 무시 = 인스턴스·기록").
- 이미 추적 중인 파일을 고치는 것은 해당하지 않는다.
- 승인된 뒤의 커밋·push 는 다시 묻지 않는다.

## 4. 커밋 전 점검

- 커밋 전에 비밀 스캔을 돌린다 (gitleaks 등 pre-commit 훅).
- 스캔 외에, 추가·변경된 추적 문서에서 §1 항목을 직접 확인한다 (`git diff --cached`).
- 공개 저장소는 push 한 순간 복제될 수 있다. history 에서 지워도 회수되지 않으므로, 비밀이 올라갔으면 즉시 그 비밀을 폐기·재발급한다.

## 5. 커밋 메시지

- 추적 문서의 변경 이력은 커밋 메시지가 갖는다 ([[변경 이력 규칙]]). 첫 줄에 무엇을 왜 바꿨는지 쓴다.
- 커밋 작성자 이메일은 GitHub noreply 주소를 쓴다. 회사·개인 이메일을 커밋에 남기지 않는다.
