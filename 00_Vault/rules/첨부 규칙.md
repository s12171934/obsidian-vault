# 첨부 규칙

> 이미지·PDF·캡처 같은 첨부의 원본 위치와 노트 안의 표기 형식을 정한다.
> 첨부의 원본은 공개 객체 저장소(R2)에 두고, 볼트의 `Attachments/` 는 업로드 전 파일이 잠시 머무는 버퍼다. 거기 남은 파일은 곧 미이관 신호다.

## 1. 원본의 위치

- 첨부 원본은 R2 버킷에 두고, 노트는 공개 URL 로만 가리킨다.
- 공개 베이스 URL·버킷·키 접두사의 실제 값은 이 공개 규칙에 적지 않는다. 그 값의 원본은 `30_Automations/` 의 첨부 업로드 설정 노트다.
- 오브젝트 키는 `<키 접두사>/<Attachments 기준 상대 경로>` 다. 파일명을 슬러그로 바꾸지 않는다 — 노트에 남은 옛 파일명 언급에서 원본을 역추적할 수 있어야 한다.
- URL 의 한글·공백은 percent-encoding 해서 적는다.
- 업로드와 크기 검증이 끝나면 `Attachments/` 의 로컬 원본을 지운다.

## 2. 노트에서의 표기

- **임베드 한 줄 + 설명 한 줄**을 쌍으로 쓴다. 둘 중 하나만 두지 않는다.

```markdown
![리팩토링 이전](https://<도메인>/<키 접두사>/%EB%A6%AC%ED%8C%A9%ED%86%A0%EB%A7%81%20%EC%9D%B4%EC%A0%84.png)

- 리팩토링 착수 전 의존성 그래프 — 파일 3,056개, 연결 621개. `core` 모듈 계열에 연결이 몰려 있다.
```

- 임베드 줄은 불릿 규칙의 예외다 — 블록 이미지로 렌더되려면 줄 전체를 차지해야 한다. 설명 줄은 불릿이다.
- alt 는 **짧은 라벨**이다. 수치와 판독 내용은 설명 줄에 적는다.
- **설명 줄은 생략할 수 없다.** 로컬 원본이 사라진 뒤로 에이전트는 파일을 직접 열 수 없다. 설명 줄이 노트 안에서 그 첨부의 유일한 판독 결과다.
- 설명에는 첨부에서 **읽어낸 값**을 적는다. "번들 분석 캡처" 같은 종류 표시는 설명이 아니다.
- 원본을 직접 봐야 하면 URL 로 가져와 확인한다. 볼트 안에 사본을 되살리지 않는다.
- `![[파일명.png]]` 위키 임베드는 쓰지 않는다 — 로컬 파일이 있다는 전제의 문법이다.

## 3. 도메인·키가 바뀔 때

- 공개 도메인이나 키 접두사를 바꾸면 설정 노트를 먼저 고치고, 볼트 전체를 grep 해 옛 URL 을 한 작업에서 일괄 치환한다. 마크다운에는 변수가 없어 URL 이 노트마다 박혀 있다.
- 두 도메인이 섞인 상태로 두지 않는다.

## 4. 올리지 않는 것

- **0바이트 파일** — 손상이다. 원본을 복구한 뒤 올린다. 그대로 올리고 로컬을 지우면 복구 단서가 사라진다.
- **어느 노트도 참조하지 않는 파일** — 참조를 만들거나 정리한다. 첨부는 노트의 근거로만 존재한다.
- **비밀·개인정보가 찍힌 캡처** — 토큰·키·쿠키·계정 정보가 보이는 화면은 올리지 않는다. 버킷이 공개이므로 URL 을 아는 누구나 열 수 있다.
